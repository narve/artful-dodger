# Project Spec

## Overview

A local image display tool with a sci-fi aesthetic. The server monitors a configured source
folder for images, auto-generates plain-text descriptions using a local LLM (Ollama), and
exposes them via a REST API. The client polls the API every 10 seconds and presents the
latest described image full-screen with a typewriter description effect, with the 4 previous
images shown as thumbnails.

## Server — `server.js`

### Tech stack

- Node.js + Express
- No database — filesystem is the source of truth

### Configuration (environment variables)

| Variable           | Description                                        | Default                  |
|--------------------|----------------------------------------------------|--------------------------|
| `SRC`              | Absolute path to the image folder                  | *(required)*             |
| `PORT`             | HTTP port                                          | `3000`                   |
| `OLLAMA_URL`       | Base URL for the local Ollama instance             | `http://localhost:11434` |
| `LLM_MODEL`        | Ollama model to use for descriptions               | `moondream`              |
| `POLL_INTERVAL_MS` | How often the worker checks for undescribed images | `5000`                   |
| `WEBCAM_ENABLE`    | Set to `1` to spawn `webcam.js` as a child process | *(unset)*                |

### Supported image formats

`.jpg`, `.jpeg`, `.png`, `.gif`, `.bmp`, `.webp`, `.tiff`, `.tif`

---

### API Endpoints

#### `GET /images`

Returns the 5 most recently captured described images, sorted by file modification time
descending (newest first).

**Response** `200 OK`

```json
[
  {
    "filename": "stage_2026-05-20_17-47-23.jpg",
    "description": "A sunset over the ocean with orange clouds."
  },
  {
    "filename": "stage_2026-05-20_17-47-18.jpg",
    "description": "A person walking along a beach."
  }
]
```

#### `GET /images/files/:filename`

Serves the raw image file directly from `SRC` via `express.static`.

- `200` + image bytes on success
- `404` if the file does not exist in `SRC`

---

### Description file format

For each image `<name>.<ext>`, the description is stored as a plain UTF-8 text file named
`<name>.<ext>.description` in the same folder as the image.

```
SRC/
├── stage_2026-05-20_17-47-23.jpg
├── stage_2026-05-20_17-47-23.jpg.description   ← generated by the worker
└── ...
```

---

### Background Worker

Runs inside the same Express process.

**Behaviour:**

1. On startup, scan `SRC` for any images without a `.description` file.
2. Every `POLL_INTERVAL_MS`, re-scan for newly added images without descriptions.
3. Process pending images **newest-first**, one at a time, to surface fresh captures quickly.
4. For each image: POST to the Ollama API, receive the description, write it to `<filename>.description`.
5. If Ollama returns an error or an empty response, log it and retry on the next cycle.

**Ollama call:**

```
POST http://OLLAMA_URL/api/generate
{
  "model": "<LLM_MODEL>",
  "prompt": "Describe this image.",
  "images": ["<base64-encoded image>"],
  "stream": false
}
```

## Client — `client/`

### Tech stack

- Vanilla HTML + CSS + JavaScript — no framework
- Single `index.html` + `style.css` + `main.js`

### Visual style

- Dark background (`#060a0d`)
- Accent color: cold cyan (`#00ffe0`)
- Monospace font throughout (`JetBrains Mono`)
- Subtle scanline overlay on the background
- Faint glowing borders/box-shadows on panels
- No buttons, no inputs — fully non-interactive display

### Layout

```
┌──────────────────────────────────────────────────────────────┐
│  SYS  ONLINE                           NEXT SCAN  8s         │  ← header
├──────────────────────────────────────────────────────────────┤
│  [thumb 4]  [thumb 3]  [thumb 2]  [thumb 1]                  │  ← archive strip
├───────────────────────┬──────────────────────────────────────┤
│                       │  IDENT  stage_2026-05-20_17-47-23    │
│                       │  CAPTURED  2026-05-20 19:47:23  8s   │
│     [MAIN IMAGE]      │  ──────────────────────────────────  │
│                       │  A woman standing in a field of      │
│                       │  tall grass, facing away from the    │
│                       │  camera...█                          │
└───────────────────────┴──────────────────────────────────────┘
```

- **Header** — system status and next-scan countdown.
- **Archive strip** — top bar showing the 4 previous images as thumbnails, newest leftmost.
  Always synced to the server's response; does not track historical display state.
- **Main image panel** — left half, image scaled to fit while preserving aspect ratio.
- **Description panel** — right half, shows filename, capture timestamp (local time),
  next-scan countdown, divider, then the description with typewriter animation.

### Polling behaviour

- Poll `GET /images` every **10 seconds**.
- Server returns the 5 latest described images (newest first).
- `images[0]` is shown as the main image if it differs from the currently displayed one.
- `images[1..4]` are always set as archive thumbnails, replacing any stale state.
- On first load with no described images: show an idle scan animation.

### Typewriter animation

- Print the description one character at a time at ~15 ms per character.
- Show a blinking block cursor (`█`) at the insertion point while typing.
- Cursor remains visible (blinking) after typing completes.
- If a new image arrives while typing is still in progress, interrupt and start fresh.

### Image serving

- Express serves image files as static assets: `GET /images/files/:filename`
- Client constructs image URLs as `http://localhost:{PORT}/images/files/{filename}`.

## Out of scope (for now)

- Authentication / access control
- Uploading images via the API
- Deleting images or descriptions via the API
- Real-time push (SSE / WebSocket) — client polls instead
