# Project Spec

## Overview

A local image display tool with a sci-fi aesthetic. The server monitors a configured source
folder for images, auto-generates plain-text descriptions using a local LLM (Ollama), and
exposes them via a REST API. The client polls the API every 10 seconds and presents each
new described image full-screen with a typewriter description effect, archiving previous
images as thumbnails.

## Server — `server/express/`

### Tech stack

- Node.js + Express
- No database — filesystem is the source of truth

### Configuration (environment variables)

| Variable           | Description                                        | Default                  |
|--------------------|----------------------------------------------------|--------------------------|
| `SRC`              | Absolute path to the image folder                  | *(required)*             |
| `PORT`             | HTTP port                                          | `3000`                   |
| `OLLAMA_URL`       | Base URL for the local Ollama instance             | `http://localhost:11434` |
| `LLM_MODEL`        | Ollama model to use for descriptions               | `moondream`              |
| `POLL_INTERVAL_MS` | How often the worker checks for undescribed images | `5000`                   |

### Supported image formats

`.jpg`, `.jpeg`, `.png`, `.gif`, `.bmp`, `.webp`, `.tiff`, `.tif`

---

### API Endpoints

#### `GET /images`

Returns all image files found in `SRC`, with their description if one exists.

**Response** `200 OK`

```json
[
  {
    "filename": "my-image.jpg",
    "described": true,
    "description": "A sunset over the ocean with orange clouds."
  },
  {
    "filename": "other.png",
    "described": false,
    "description": null
  }
]
```

#### `GET /images/:filename`

Returns metadata and description for a single image.

**Response** `200 OK`

```json
{
  "filename": "my-image.jpg",
  "described": true,
  "description": "A sunset over the ocean with orange clouds."
}
```

**Errors**

- `404` — file not found in `SRC`

#### `GET /images/files/:filename`

Serves the raw image file directly from `SRC` via `express.static`.

- `200` + image bytes on success
- `404` if the file does not exist in `SRC`

---

### Description file format

For each image `<name>.<ext>`, the description is stored as a plain UTF-8 text file named
`<name>.<ext>.description` in the same folder as the image.

Example:

```
SRC/
├── my-image.jpg
├── my-image.jpg.description   ← generated by the worker
├── other.png
└── ...
```

---

### Background Worker

Runs inside the same Express process.

**Behaviour:**

1. On startup, scan `SRC` for any images that have no `.description` file and queue them.
2. Every `POLL_INTERVAL_MS`, re-scan `SRC` for newly added images without descriptions and add them to the queue.
3. Process the queue **one image at a time** (sequential, not concurrent) to avoid overwhelming the LLM.
4. For each image: POST to the Ollama API, receive the description, write it to `<filename>.description`.
5. If Ollama returns an error, log it and move on — retry on the next poll cycle.

**Ollama call:**

```
POST http://OLLAMA_URL/api/generate
{
  "model": "<LLM_MODEL>",
  "prompt": "Describe this image.",
  "images": ["<base64-encoded image>"],
  "stream": false
}
```

## Client — `client/`

### Tech stack

- Vanilla HTML + CSS + JavaScript — no framework
- Single `index.html` + `style.css` + `main.js`

### Visual style

- Dark background (`#000` or near-black)
- Accent color: cold cyan/green (e.g. `#00ffe0` or `#39ff14`)
- Monospace font throughout (e.g. `JetBrains Mono`, `Fira Code`, or system `monospace`)
- Subtle scan-line or grid overlay on the background
- Faint glowing borders/box-shadows on panels
- No buttons, no inputs — fully non-interactive display

### Layout

```
┌──────────────────────────────────────────────────────────────┐
│  [thumb 3]  [thumb 2]  [thumb 1]                             │  ← archive strip (top)
├───────────────────────┬──────────────────────────────────────┤
│                       │  > IDENT: my-image.jpg               │
│                       │  ──────────────────────────────────  │
│     [MAIN IMAGE]      │  A woman standing in a field of      │
│                       │  tall grass, facing away from the    │
│                       │  camera...█                          │
└───────────────────────┴──────────────────────────────────────┘
```

- **Archive strip** — top bar showing the 3–5 most recently displayed images as small
  thumbnails, ordered newest-to-oldest from right to left (closest to the main view).
- **Main image panel** — left half, image scaled to fit while preserving aspect ratio.
- **Description panel** — right half, monospace text with typewriter animation.

### Polling behaviour

- Poll `GET /images` every **10 seconds**.
- Only images with `described: true` are considered for display.
- The API response is sorted by filename; the client tracks which filename was last shown.
- When a previously-unseen described image is detected:
    1. Animate the current main image shrinking and sliding into the archive strip (CSS transition).
    2. If the archive strip already has 5 thumbnails, drop the oldest.
    3. Fade/slide the new image into the main panel.
    4. Start the typewriter animation on the description (character-by-character, ~30 ms/char).
- On first load with no described images: show an idle scan animation in both panels.

### Typewriter animation

- Print the description one character at a time at ~30 ms per character.
- Show a blinking block cursor (`█`) at the insertion point while typing.
- Cursor remains visible (blinking) after typing completes.
- If a new image arrives while typing is still in progress, interrupt and transition immediately.

### Image serving

- Express serves image files as static assets: `GET /images/files/:filename`
- Implemented with a single `express.static(SRC)` mount — no extra server needed.
- Client constructs image URLs as `http://localhost:{PORT}/images/files/{filename}`.

---

## Out of scope (for now)

- Authentication / access control
- Uploading images via the API
- Deleting images or descriptions via the API
- Real-time push (SSE / WebSocket) — client polls instead
